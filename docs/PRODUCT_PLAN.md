# AI News — 产品计划书

> AI 新闻聚合日报工具 → **话题追踪引擎**。从多源 RSS 抓取 AI 相关新闻，翻译、汇总为 Markdown 日报，推送到飞书 / 生成小红书发布内容。下一阶段将进化为用户驱动的通用话题追踪系统。

## 🎯 产品愿景

> **用户关注什么，系统就持续跟踪什么。**
>
> 不管是一个突发热点（"OpenAI 发布 GPT-5"），还是长期兴趣（"人形机器人进展"），你只需在飞书告诉 Bot 一声，系统就自动从多源（新闻/社区/博客）汇总相关信息，形成有序的时间线或定期简报。当你说"够了"，它就不再追踪。
>
> 从被动接收日报，到主动订阅话题。

**核心原则：**
1. **零依赖付费 API** — 所有服务使用免费层或低成本的轻量云服务器
2. **内容为王** — 持续优化信息质量，确保每条追踪结果有价值
3. **渐进增强** — 每次只解决一个问题，每步可独立上线
4. **飞书即界面** — Bot 交互在前，Web 界面在后
5. **一人起步，少数人试用** — 先从个人工具做起，再扩展为小范围共享服务

### Phase 5 — 话题追踪引擎 ⏳ 未来阶段
> 目标：将项目从"AI 日报"进化为用户驱动的话题追踪系统

| 功能 | 预估工时 |
|------|---------|
| 信源扩展（澎湃、新华社、南方周末等新闻源） | 2 h |
| 自动判断追踪模式：短期热点 vs 长期订阅 | 1.5 h |
| 短期热点追踪：时间线生成（按小时/天汇聚） | 2 h |
| 长期信息订阅：定期简报（与当前日报类似） | 1 h |
| 主题匹配引擎（关键词 → 从多源检索相关内容） | 2 h |
| 订阅管理 CRUD（SQLite 存储 + Bot 命令） | 1.5 h |
| 生命周期管理（用户手动停止 / 热点自动过期） | 1 h |
| 已读/未读标记（增量阅读支持） | 1 h |
| 时间线可视化沉淀（Markdown 格式输出） | 1 h |

**两种追踪模式：**

| 维度 | 短期热点追踪 | 长期信息订阅 |
|------|------------|------------|
| 触发条件 | 用户指定+时效性（如 "追踪 XX 发布会"） | 用户长期兴趣 |
| 检查频率 | 按小时 | 每天一次 |
| 输出形式 | 追加时间线（新增事件排序） | 每日简报 |
| 生命周期 | 用户停止 / 预设时间到期自动结束 | 持续到用户取消 |
| 时间线变化 | ✅ 显示"事件演变" | ❌ 不需要 |

**当前 AI 日报定位：**
- 作为系统的一个默认预配置订阅实例
- 主题："AI 新闻"
- 模式：长期信息订阅
- 信源：7 个 AI/科技 RSS
- 输出：每日简报 + 飞书推送

**信源扩展策略：**

| 类型 | 示例 | 接入方式 | 优先级 |
|------|------|---------|-------|
| 新闻媒体（有 RSS） | 澎湃、新华社、南方周末 | RSS（15 min/个） | ⭐⭐⭐ |
| 新闻媒体（无 RSS） | 待评估 | Web scraping | ⭐⭐ |
| 技术社区 | Hacker News、知乎、虎扑 | RSS(有)+Scraping(无) | ⭐（背锅） |

知乎和虎扑等社区源涉及反爬、登录态维护、DOM 选择器易失效，维护成本极高（约 3-5 小时安装 + 月度维护），**建议在架构稳定运行后单独评估，不在 Phase 5 的初始范围内。**

**交付物：**
- 通过飞书 Bot 可订阅任意主题
- 系统自动判断追踪模式，按合适频率执行
- 短期热点可查看时间线变化
- 当前 AI 日报作为系统默认订阅共存

## 🔄 迭代原则

1. **每次只做一个 Phase** — 完成验证后再进入下一个
2. **每个 Phase 包含测试** — 无论多简单
3. **先手动验证，再启用自动调度** — 避免定时任务静默失败
4. **文档同步更新** — 功能做完时文档也是最新的
5. **一人起步 → 少数人试用 → 再考虑扩容** — 不超前设计
